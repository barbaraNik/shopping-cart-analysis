# shopping-cart-analysis

## Решение тестовых заданий для интернет-магазина "Петрушка Зеленая", включающее анализ требований, проектирование REST API и архитектуру push-уведомлений.

Данный репозиторий содержит полное решение задания, включающее анализ технического задания, проектирование REST API и разработку архитектуры системы push-уведомлений для высоконагруженного e-commerce приложения

### Контекст

"Петрушка Зеленая" — e-commerce платформа, которая динамично развивается.
Есть три критические задачи:

**1. Анализ требований**
- Техническое задание функционала корзины содержит логические противоречия
- Требуется найти все проблемы и предложить исправленную версию ТЗ
- Результат будет использован при разработке корзины

**2. Проектирование API**
- Компания расширяет функционал и добавляет экран с магазинами-партнерами
- Требуется спроектировать REST API для этого экрана
- API должен быть готовым к использованию на фронтенде

**3. Архитектура системы уведомлений**
- Платформе требуется система отправки push-уведомлений
- Требуется спроектировать надежную, масштабируемую архитектуру

### Бизнес-цели

1. Избежать логических противоречий в требованиях на стадии ТЗ  
2. Спроектировать REST API  
3. Построить надежную систему уведомлений для большого числа пользователей

---

## Что я делала

### Анализ требований

**Задача:** Найти логические противоречия в техническом задании функционала корзины.

**Решение:**
- Найдено 3 основных противоречия и 3 недочета
- Сформирован список вопросов к ПМ и бизнес-заказчику

**Результат:** ТЗ обновлено и структурировано, готово к дальнейшим корректировкам в зависимости от ответов ПМ и бизнес-заказчика, выделены основные разделы ТЗ

---

### Проектирование API

**Задача:** Спроектировать REST API для экрана партнерских магазинов.

**Результат:** сформирована REST API Спецификация, в которое прописаны query параметры, описаны ошибки и введен External URL для перехода к партнёр на сторонние сайты

---

### Архитектура системы push-уведомлений

**Задача:** Спроектировать архитектуру для отправки push-уведомлений в день.

**Результат:** Выбран брокер сообщений, обоснован выбор в пользу данного брокер сообщений, сделана диаграмма отправки пушей клиентам
